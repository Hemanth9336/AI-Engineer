You have three days to build a PoC for Harbor Foods' supplier desk. Your list of possible work is longer than three days.

### Q1. Which item is safe to cut?

- A. Refusing questions the handbook doesn't cover
- B. Citing the handbook section
- C. A web UI - a command-line script is enough for a PoC demo
- D. Using Harbor Foods' real handbook

<details><summary>Answer</summary>

**Answer: C** - UI is cuttable; citations, refusals and real data are the point.

</details>

### Q2. Which shortcut is NOT acceptable even in a PoC?

- A. Pasting the API key into the script you share with the customer's IT team
- B. Recomputing embeddings on every call
- C. No logging
- D. No Zendesk integration

<details><summary>Answer</summary>

**Answer: A** - Leaked credentials are a real incident, PoC or not.

</details>

### Q3. How do you make sure nobody mistakes the PoC for a product?

- A. Hide the code
- B. Only demo it once
- C. Make it look rough
- D. Write down what was cut and what production needs, and walk through it at the demo

<details><summary>Answer</summary>

**Answer: D** - An explicit list of shortcuts sets expectations.

</details>
